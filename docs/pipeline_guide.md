# Гибридный пайплайн оценки загрузки

## Что решает пайплайн

Пайплайн прогнозирует `load_pct` — экспертную оценку заполнения грузового отсека в процентах от 0 до 100. Это оценка занятой площади пола, а не массы груза и не доли грузоподъёмности.

Основной режим соединяет две ветки:

1. 349 числовых признаков изображения: геометрия и маска кузова, цвет, текстура, доля синего, признаки свободного пола, потолка и их взаимного расположения.
2. CNN с ResNet18: визуальные признаки замаскированной области кузова.

Общая регрессионная голова получает оба вектора и возвращает один прогноз. Вспомогательные головы CNN классифицируют `load_bin` и `cargo_type` только при обучении; в submission они не попадают.

```text
исходная фотография
  → сегментация кузова
  → bbox кузова + маска
  ├─ 349 числовых признаков
  └─ CNN: тот же bbox, пиксели вне кузова обнулены
       → CNN-вектор + нормализованные 349 признаков
       → общая голова → load_pct в [0, 100]
```

## Что требуется до запуска

Запускайте команды из корня репозитория. Используйте существующее окружение `venv`.

```powershell
.\venv\Scripts\python.exe --version
.\venv\Scripts\python.exe .\src\baseline.py train --help
```

Для гибридного обучения должны существовать:

```text

DataSet/train/images/<image_id>.jpg
```

Первый запуск CNN без `--no-pretrained` использует ImageNet-веса ResNet18 через `timm`. Если их ещё нет в локальном кэше, нужен доступ к сети для их скачивания. `--no-pretrained` отключает скачивание и начинает обучение CNN со случайных весов; обычно это ухудшает качество.

Для GPU проверьте, что PyTorch видит CUDA:

```powershell
.\venv\Scripts\python.exe -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

## Входные таблицы

`train_split.csv` и `validation_split.csv` должны иметь следующие колонки:

```text
image_id,load_pct,group_id,load_bin,vehicle_type,viewpoint,lighting,cargo_type
```

`image_id` задаётся без расширения; изображение находится по пути `<images>/<image_id>.jpg`.

Перед обучением `report.py` проверяет непустые и уникальные ID, диапазон `load_pct`, отсутствие пересечений `image_id` и `group_id` между train и validation. Гибрид дополнительно проверяет категории `load_bin` и `cargo_type`, а также наличие каждого изображения.

`test.csv` для предикта должен состоять ровно из одного столбца:

```text
image_id
```

Порядок строк в submission сохраняется таким же, как в `test.csv`.

### Этапы команды `train`

1. `src/baseline.py` разбирает CLI. Значение `--method hybrid` выбрано по умолчанию и передаёт управление в `src/hybrid/hybrid.py::train`.
2. `src/hybrid/hybrid.py` проверяет параметры, отсутствие уже существующих выходных файлов, доступность CUDA при её выборе и корректность train/validation split.
3. `src/hybrid/hybrid_features.py::build_contract` вычисляет SHA-256 трёх сегментационных checkpoint-файлов, исходников обработки и версий библиотек. Эта информация становится частью будущей модели.
4. `src/hybrid/hybrid_features.py::cached_samples` создаёт или переиспользует кэш. Ключ кэша зависит от содержимого фотографии и contract. Поэтому изменение фотографии, исходников обработки или сегментационных весов приводит к созданию нового cache entry.
5. Для каждого cache entry `src/manual/features.py::extract_hybrid_sample` читает изображение в RGB, строит маску кузова, вырезает bbox и создаёт два согласованных входа:
   - массив из 349 числовых признаков;
   - RGB ROI для CNN, где пиксели за пределами маски кузова внутри bbox заменены на нули.
6. `src/hybrid/hybrid.py::HybridDataset` читает ROI из кэша, делает letterbox до `320×320`, нормализует ImageNet mean/std и формирует PyTorch tensor. На текущей версии гибрида случайные аугментации не используются: CNN и числовая ветка видят одну и ту же исходную область кузова.
7. Среднее и стандартное отклонение 349 признаков рассчитываются только по train. Нулевые стандартные отклонения заменяются на 1.
8. `src/CNN/model.py::HybridTruckLoadNet` создаёт ResNet18. На первой фазе backbone заморожен, а на второй размораживается. BatchNorm замороженного backbone остаётся в eval-режиме.
9. После каждой эпохи считается MAE на фиксированной validation. Лучшая эпоха сохраняется в памяти и затем записывается отдельным validation checkpoint.
10. Из лучших validation-прогнозов создаётся CSV ошибок. Затем новый экземпляр модели обучается на объединении train и validation ровно столько эпох, сколько выбрано по validation. Это финальная модель для predict.

Свободный пол извлекается внутри ROI кузова:

1. ROI и маска кузова приводятся к `320×320`.
2. `src/manual/floor_segmentation/runtime.py` загружает FloorUNet и прогнозирует маску свободного пола.
3. Маска чистится морфологическими операциями и ограничивается кузовом.
4. Рассчитываются глобальная и взвешенная площади пола, показатели нижних 75% кадра, 8 depth-bin, 3 near/mid/far агрегата, 8 показателей ширины, 3 агрегата ширины, глубина пола по трём вертикальным полосам, статистики глубины, связные компоненты и bbox/centroid геометрия.

Если маска кузова пуста, базовая функция crop использует полный кадр как ROI и маску из единиц. Это fallback для плохой сегментации; его доля в данных должна быть проверена отдельно по логам/визуализациям.

### Расчёт признаков в версии v2

- При отсутствии `ceiling_weights_path` используется стандартный checkpoint
  потолка. Его порог берётся из checkpoint. Явно указанный отсутствующий файл
  вызывает ошибку, а не заменяется стандартными весами.
- Для цветовых и текстурных признаков RGB умножается на бинарную маску;
  произведение и маска уменьшаются одинаковой линейной интерполяцией.
  Затем RGB делится на вес маски. Поэтому пиксели фона не влияют на эти
  признаки и не затемняют границу. Ячейки без валидных пикселей дают нули.
- Глубина пола/потолка считается одним симметричным алгоритмом. Связная
  компонента должна пересекать последние/первые 10 строк кузова хотя бы
  в одном столбце полосы. Это допуск на погрешность сегментации.
- Верх, низ и высота кузова определяются по `truck_mask` отдельно в каждом
  столбце. Для выбранных компонент берётся максимальное расстояние от
  соответствующей границы, делённое на локальную высоту кузова. Результат
  лежит в `[0, 1]`. Оторванные от граничной зоны компоненты дают ноль.

Это признаки изображения, а не измерение реальной площади или глубины.
Доля синего не различает груз и синий фон внутри кузова. Взвешенные площади,
зеркальные depth bins, `cargo_front` и `far_shell_visible_ratio` остаются
эвристиками. Последний — среднее двух профилей, а не площадь объединения
масок в единой дальней области. Пользу этих признаков нужно проверять
сравнением наборов признаков на фиксированной validation.

## Как работает нейросеть

Реализация находится в `src/CNN/model.py`, в классе `HybridTruckLoadNet`. Это не отдельная CNN, которая сначала выдаёт собственный прогноз, а визуальная ветка общей гибридной модели.

### Вход CNN

1. `src/manual/truck_segmentation/runtime.py` строит бинарную маску грузового отсека.
2. Из изображения берётся bbox кузова. Пиксели за пределами маски внутри bbox заменяются нулями.
3. Masked ROI приводится letterbox-преобразованием к `3×320×320` и нормализуется по ImageNet mean/std.
4. Числовая ветка получает признаки из того же ROI, поэтому CNN и 349 признаков описывают одну область изображения.

### Архитектура и выходы

1. `timm.create_model("resnet18", pretrained=..., num_classes=0, global_pool="avg")` создаёт ResNet18 без стандартного ImageNet-классификатора.
2. Backbone превращает изображение в усреднённый визуальный вектор `visual`.
3. Этот вектор объединяется с нормализованным вектором из 349 числовых признаков.
4. Регрессионная голова имеет структуру `Linear → ReLU → Dropout → Linear → sigmoid × 100` и выдаёт `load_pct` в диапазоне `[0, 100]`.
5. Две вспомогательные головы получают только `visual` и предсказывают 10 классов `load_bin` и 5 классов `cargo_type`. Их прогнозы не записываются в submission, а используются как дополнительный обучающий сигнал.

### Фазы обучения

1. Фаза 1 (`--phase1-epochs`, по умолчанию 6): ResNet18 заморожен, обучаются регрессионная и auxiliary-головы.
2. Фаза 2 (`--phase2-epochs`, по умолчанию 18): ResNet18 размораживается и дообучается с меньшим `--backbone-lr`; головы продолжают обучаться с `--head-lr`.

Функция потерь:

Функция потерь в обучении:

```text
L1(load_pct, target) + aux_weight × [CrossEntropy(load_bin) + CrossEntropy(cargo_type)]
```

## Выходы обучения

При `--model .\models\hybridV1.npz` создаются:

| Файл | Назначение |
| --- | --- |
| `models/hybridV1.validation.npz` | Модель лучшей validation-эпохи; используется для доказуемой локальной метрики |
| `models/hybridV1.npz` | Финальная модель, обученная на train + validation; используется в predict |
| `models/hybridV1.json` | Метрики, параметры, история эпох, contract сегментаторов и пути артефактов |
| `models/hybridV1_errors.csv` | Ошибки validation, отсортированные по убыванию абсолютной ошибки |
| `models/hybrid_feature_cache/*.npz` | Кэш 349 признаков и masked ROI |

Финальная модель не получает MAE на validation в качестве независимой метрики: validation использовалась для выбора числа эпох и затем вошла в финальное обучение. Смотрите `hybrid` в JSON как локальный результат validation checkpoint.

Модель хранится в NPZ без pickle: JSON-конфигурация и массивы `state_dict`. При predict загрузка использует `allow_pickle=False`.

## Прогноз на test

После успешного обучения:

```powershell
.\venv\Scripts\python.exe .\src\baseline.py predict `
  --model .\models\hybridV1.npz `
  --output .\output_csv\hybridV1_submission.csv `
  --device cuda `
  --batch-size 16
```

На CPU замените `--device cuda` на `--device cpu` и уменьшите batch-size при нехватке памяти.

Этапы `predict`:

1. `src/predict.py` читает метод из файла модели и передаёт hybrid-модель в `src/hybrid/hybrid.py::predict`.
2. Из metadata модели читаются contract, preprocessing и параметры CNN.
3. Текущие сегментационные веса сверяются с SHA-256, сохранёнными при обучении. Несовпадение останавливает predict: смешивать изменённую обработку с прежними весами нельзя.
4. Для тестовых изображений создаются или переиспользуются cache entries из masked ROI и 349 признаков.
5. CNN и числовая ветка формируют прогнозы; проверяются конечность и диапазон `[0, 100]`.
6. `src/submission.py` записывает CSV с заголовком `image_id,load_pct`. Количество прогнозов обязано совпадать с числом входных ID.

## Совместимость признаков и старых моделей

Текущая версия обработки — `truck-floor-ceiling-cross-349-masked-roi-v2`.
Порядок и число признаков сохранены, но изменены расчёт глубины и уменьшение
RGB внутри маски. Гибрид проверяет версию и SHA-256 исходников/весов через
feature contract: старые кэши не переиспользуются, старые модели отвергаются.

Регрессоры с 233/235/277 признаками (включая прежнюю V10) и модели на прежних
349 признаках требуют переобучения. Для Ridge/boosting полной проверки
feature contract нет: совпадения числа признаков недостаточно, поэтому
использовать прежние веса с новой обработкой нельзя.

## Веса CNN и checkpoint-ы

При запуске `train` гибрид создаёт модель заново:

- без `--no-pretrained` ResNet18 получает стартовые ImageNet-веса через `timm`; если их нет в кэше, нужен доступ к сети;
- с `--no-pretrained` ResNet18 начинает со случайных весов;
- веса `truck`, `floor` и `ceiling` являются отдельными моделями сегментации и не являются весами CNN гибрида;
- файлы `src/CNN/models/fold*_best.pt` от отдельного эксперимента `train_cnn.py` автоматически не загружаются: их регрессионная голова не рассчитана на объединение с 349 признаками.

После обучения отдельный файл весов CNN не создаётся. CNN входит в состав гибридного checkpoint-а:

- `*.validation.npz` содержит backbone, все головы и нормализацию модели, обученной только на train; это checkpoint лучшей эпохи по validation;
- `*.npz` содержит backbone, все головы и нормализацию финальной модели, обученной на train + validation; этот файл используется для predict;
- `.json` содержит metadata, параметры CNN, contract сегментации, историю обучения и роль checkpoint-а.

Формат `.npz` не использует pickle: `src/hybrid/hybrid_artifacts.py` сохраняет массивы `state.*`, metadata и номер формата. При predict модель создаётся с `pretrained=False`, затем в неё загружается сохранённый `state_dict`, поэтому повторное скачивание ImageNet-весов не требуется.

Параметра `--cnn-init` в текущем CLI нет. Полностью подставлять checkpoint отдельной CNN нельзя: гибридная регрессионная голова принимает `visual + 349` признаков. Теоретически можно отдельно перенести совместимые `backbone.*`, `load_bin_head.*` и `cargo_type_head.*`, но для этого нужна специальная загрузка с проверкой формата.

## Ограничения текущего состояния

- После изменения признаков требуется полное переобучение на готовом разбиении. Короткая техническая проверка на подмножестве данных не оценивает качество модели.
- MAE новой версии на полном фиксированном validation пока не проверен; отдельный файл CNN-весов не создаётся.
- Не заменяйте сегментационные веса между train и predict. Contract намеренно остановит predict при несовпадении.
- Сегментация кузова, пола и потолка добавляет существенное время на первом проходе. Повторный запуск с теми же фото, весами и кодом переиспользует кэш ROI/признаков.
- XML API, хранение результата по номеру перевозки и сервисная обработка ошибок не входят в этот CLI-пайплайн.
