# Гибридный пайплайн оценки загрузки

## Что решает пайплайн

Пайплайн прогнозирует `load_pct` — экспертную оценку заполнения грузового отсека в процентах от 0 до 100. Это оценка занятой площади пола, а не массы груза и не доли грузоподъёмности.

Основной режим соединяет две ветки:

1. 277 числовых признаков изображения: геометрия и маска кузова, цвет, текстура, синий груз и признаки свободного пола.
2. CNN с ResNet18: визуальные признаки замаскированной области кузова.

Общая регрессионная голова получает оба вектора и возвращает один прогноз. Вспомогательные головы CNN классифицируют `load_bin` и `cargo_type` только при обучении; в submission они не попадают.

```text
исходная фотография
  → сегментация кузова
  → bbox кузова + маска
  ├─ 277 числовых признаков
  └─ CNN: тот же bbox, пиксели вне кузова обнулены
       → CNN-вектор + нормализованные 277 признаков
       → общая голова → load_pct в [0, 100]
```

## Что требуется до запуска

Запускайте команды из корня репозитория. Используйте существующее окружение `venv`.

```powershell
.\venv\Scripts\python.exe --version
.\venv\Scripts\python.exe .\src\baseline.py train --help
```

Для гибридного обучения должны существовать:

```text
DataSet/train/train_split.csv
DataSet/train/validation_split.csv
DataSet/train/images/<image_id>.jpg
src/segmentation/models/best_unet_resnet18.pth
src/floor_segmentation/models/floor_unet_resnet18_lr1e3.best_loss.pt
```

Первый запуск CNN без `--no-pretrained` использует ImageNet-веса ResNet18 через `timm`. Если их ещё нет в локальном кэше, нужен доступ к сети для их скачивания. `--no-pretrained` отключает скачивание и начинает обучение CNN со случайных весов; обычно это ухудшает качество.

Для GPU проверьте, что PyTorch видит CUDA:

```powershell
.\venv\Scripts\python.exe -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

## Входные таблицы

`train_split.csv` и `validation_split.csv` должны иметь следующие колонки:

```text
image_id,load_pct,group_id,load_bin,vehicle_type,viewpoint,lighting,cargo_type
```

`image_id` задаётся без расширения; изображение находится по пути `<images>/<image_id>.jpg`.

Перед обучением `report.py` проверяет непустые и уникальные ID, диапазон `load_pct`, отсутствие пересечений `image_id` и `group_id` между train и validation. Гибрид дополнительно проверяет категории `load_bin` и `cargo_type`, а также наличие каждого изображения.

`test.csv` для предикта должен состоять ровно из одного столбца:

```text
image_id
```

Порядок строк в submission сохраняется таким же, как в `test.csv`.

## Обучение

### GPU

Укажите новые имена файлов. Не используйте `baselineV10.*`: это сохранённый результат предыдущей ветки.

```powershell
.\venv\Scripts\python.exe .\src\baseline.py train `
  --model .\models\hybridV1.npz `
  --errors-output .\models\hybridV1_errors.csv `
  --device cuda `
  --amp `
  --batch-size 16
```

### CPU

CPU-вариант значительно медленнее. `--amp` для CPU не указывайте.

```powershell
.\venv\Scripts\python.exe .\src\baseline.py train `
  --model .\models\hybridV1.npz `
  --errors-output .\models\hybridV1_errors.csv `
  --device cpu `
  --batch-size 4
```

Параметры по умолчанию:

| Параметр | Значение | Назначение |
|---|---:|---|
| `--backbone` | `resnet18` | CNN-backbone timm |
| `--img-size` | `320` | Размер letterbox-входа CNN |
| `--phase1-epochs` | `6` | Эпохи с замороженным backbone |
| `--phase2-epochs` | `18` | Эпохи с размороженным backbone |
| `--head-lr` | `0.001` | Скорость обучения голов |
| `--backbone-lr` | `0.0001` | Скорость обучения backbone на второй фазе |
| `--aux-weight` | `0.2` | Вес двух вспомогательных классификационных loss |
| `--patience` | `6` | Early stopping на второй фазе |
| `--seed` | `42` | Seed Python, NumPy и PyTorch |
| `--num-workers` | `0` | Число DataLoader-процессов; для Windows безопасно оставить 0 |

Можно явно задать пути сегментационных весов и каталог кэша:

```powershell
--truck-weights .\src\segmentation\models\best_unet_resnet18.pth `
--floor-weights .\src\floor_segmentation\models\floor_unet_resnet18_lr1e3.best_loss.pt `
--feature-cache .\models\hybridV1_feature_cache
```

Эти пути обычно указывать не нужно: они являются значениями по умолчанию.

### Этапы команды `train`

1. `src/baseline.py` разбирает CLI. Значение `--method hybrid` выбрано по умолчанию и передаёт управление в `src/hybrid.py::train`.
2. `hybrid.py` проверяет параметры, отсутствие уже существующих выходных файлов, доступность CUDA при её выборе и корректность train/validation split.
3. `src/hybrid_features.py::build_contract` вычисляет SHA-256 обоих сегментационных checkpoint-файлов, исходников обработки и версий библиотек. Эта информация становится частью будущей модели.
4. `hybrid_features.py::cached_samples` создаёт или переиспользует кэш. Ключ кэша зависит от содержимого фотографии и contract. Поэтому изменение фотографии, исходников обработки или сегментационных весов приводит к созданию нового cache entry.
5. Для каждого cache entry `src/features.py::extract_hybrid_sample` читает изображение в RGB, строит маску кузова, вырезает bbox и создаёт два согласованных входа:
   - массив из 277 числовых признаков;
   - RGB ROI для CNN, где пиксели за пределами маски кузова внутри bbox заменены на нули.
6. `src/hybrid.py::HybridDataset` читает ROI из кэша, делает letterbox до `320×320`, нормализует ImageNet mean/std и формирует PyTorch tensor. На первой версии гибрида не используются случайные аугментации: CNN и числовая ветка видят одну и ту же исходную область кузова.
7. Среднее и стандартное отклонение 277 признаков рассчитываются только по train. Нулевые стандартные отклонения заменяются на 1.
8. `src/model.py::HybridTruckLoadNet` создаёт ResNet18. На первой фазе backbone заморожен, а на второй размораживается. BatchNorm замороженного backbone остаётся в eval-режиме.
9. После каждой эпохи считается MAE на фиксированной validation. Лучшая эпоха сохраняется в памяти и затем записывается отдельным validation checkpoint.
10. Из лучших validation-прогнозов создаётся CSV ошибок. Затем новый экземпляр модели обучается на объединении train и validation ровно столько эпох, сколько выбрано по validation. Это финальная модель для predict.

## Как образуются 277 признаков

`src/features.py` формирует 235 базовых и 42 floor-признака.

| Группа | Количество | Содержание |
|---|---:|---|
| Пространственный цвет | 192 | Средний RGB в сетке `8×8` внутри маски кузова |
| Текстура | 16 | Стандартное отклонение яркости в сетке `4×4` |
| Гистограммы | 24 | По 8 bin для каждого RGB-канала |
| Глобальные признаки | 3 | Aspect ratio исходного фото, доля синего груза внутри кузова, доля маски кузова в исходном кадре |
| Свободный пол | 42 | Площадь, глубинный профиль, ширина, связность и геометрия свободного пола |
| **Всего** | **277** | Вектор числовой ветки |

Свободный пол извлекается внутри ROI кузова:

1. ROI и маска кузова приводятся к `320×320`.
2. `floor_segmentation/runtime.py` загружает FloorUNet и прогнозирует маску свободного пола.
3. Маска чистится морфологическими операциями и ограничивается кузовом.
4. Рассчитываются глобальная и взвешенная площади пола, показатели нижних 75% кадра, 8 depth-bin, 3 near/mid/far агрегата, 8 показателей ширины, 3 агрегата ширины, глубина пола по трём вертикальным полосам, статистики глубины, связные компоненты и bbox/centroid геометрия.

Если маска кузова пуста, базовая функция crop использует полный кадр как ROI и маску из единиц. Это fallback для плохой сегментации; его доля в данных должна быть проверена отдельно по логам/визуализациям.

## Как работает нейросеть

`HybridTruckLoadNet` в `src/model.py`:

1. ResNet18 получает masked ROI `3×320×320` и выдаёт визуальный вектор.
2. 277 числовых признаков нормализуются параметрами, сохранёнными в модели.
3. Визуальный и числовой векторы объединяются.
4. Общая регрессионная голова `Linear → ReLU → Dropout → Linear → sigmoid × 100` выдаёт `load_pct` в диапазоне `[0, 100]`.
5. Две auxiliary головы получают только CNN-вектор и предсказывают 10 интервалов загрузки и 5 типов груза. Их loss помогает обучению, но не участвует в CSV результата.

Функция потерь в обучении:

```text
L1(load_pct, target) + aux_weight × [CrossEntropy(load_bin) + CrossEntropy(cargo_type)]
```

## Выходы обучения

При `--model .\models\hybridV1.npz` создаются:

| Файл | Назначение |
|---|---|
| `models/hybridV1.validation.npz` | Модель лучшей validation-эпохи; используется для доказуемой локальной метрики |
| `models/hybridV1.npz` | Финальная модель, обученная на train + validation; используется в predict |
| `models/hybridV1.json` | Метрики, параметры, история эпох, contract сегментаторов и пути артефактов |
| `models/hybridV1_errors.csv` | Ошибки validation, отсортированные по убыванию абсолютной ошибки |
| `models/hybrid_feature_cache/*.npz` | Кэш 277 признаков и masked ROI |

Финальная модель не получает MAE на validation в качестве независимой метрики: validation использовалась для выбора числа эпох и затем вошла в финальное обучение. Смотрите `hybrid` в JSON как локальный результат validation checkpoint.

Модель хранится в NPZ без pickle: JSON-конфигурация и массивы `state_dict`. При predict загрузка использует `allow_pickle=False`.

## Прогноз на test

После успешного обучения:

```powershell
.\venv\Scripts\python.exe .\src\baseline.py predict `
  --model .\models\hybridV1.npz `
  --output .\output_csv\hybridV1_submission.csv `
  --device cuda `
  --batch-size 16
```

На CPU замените `--device cuda` на `--device cpu` и уменьшите batch-size при нехватке памяти.

Этапы `predict`:

1. `src/predict.py` читает метод из файла модели и передаёт hybrid-модель в `src/hybrid.py::predict`.
2. Из metadata модели читаются contract, preprocessing и параметры CNN.
3. Текущие сегментационные веса сверяются с SHA-256, сохранёнными при обучении. Несовпадение останавливает predict: смешивать изменённую обработку с прежними весами нельзя.
4. Для тестовых изображений создаются или переиспользуются cache entries из masked ROI и 277 признаков.
5. CNN и числовая ветка формируют прогнозы; проверяются конечность и диапазон `[0, 100]`.
6. `src/submission.py` записывает CSV с заголовком `image_id,load_pct`. Количество прогнозов обязано совпадать с числом входных ID.

## Старая V10 и совместимость

`models/baselineV10.pkl` — текущая отдельная boosting-модель с 277 признаками. Она не является checkpoint гибрида и не используется как начальные веса CNN. Гибрид использует тот же алгоритм 277 признаков, но учится заново вместе с CNN.

Для запуска старого регрессионного пути явно укажите не-hybrid метод при обучении:

```powershell
.\venv\Scripts\python.exe .\src\baseline.py train `
  --method auto `
  --model .\models\baseline_experiment.npz `
  --errors-output .\models\baseline_experiment_errors.csv
```

Для прогноза V10 указывайте именно существующий `.pkl`:

```powershell
.\venv\Scripts\python.exe .\src\baseline.py predict `
  --model .\models\baselineV10.pkl `
  --output .\output_csv\baselineV10_submission.csv
```

Старые `.npz` с 233/235 признаками не совместимы с текущим извлечением 277 признаков.

## Веса CNN друга

Текущий гибрид не содержит параметра `--cnn-init`: сторонний checkpoint CNN пока не загружается автоматически. До его появления гибрид начинает обучение с ImageNet-ResNet18 либо со случайных весов при `--no-pretrained`.

Если появится checkpoint из прежнего `train_cnn.py`, его нельзя полностью подставить вместо гибрида: старая регрессионная голова не знает 277 новых числовых признаков. Для инициализации можно будет перенести совместимые `backbone.*`, `load_bin_head.*` и `cargo_type_head.*`, оставив новую регрессионную голову гибрида случайной. Это требует отдельного добавления `--cnn-init` и проверки формата checkpoint.

## Ограничения текущего состояния

- Реальное обучение и predict на `DataSet` для гибрида ещё не запускались; MAE гибрида неизвестен.
- Нужна первая тяжёлая тренировка CNN. После неё финальные `hybridV1.npz` и JSON появятся в `models`.
- Не заменяйте сегментационные веса между train и predict. Contract намеренно остановит predict при несовпадении.
- Сегментация кузова и пола добавляет существенное время на первом проходе. Повторный запуск с теми же фото, весами и кодом переиспользует кэш ROI/признаков.
- XML API, хранение результата по номеру перевозки и сервисная обработка ошибок не входят в этот CLI-пайплайн.
