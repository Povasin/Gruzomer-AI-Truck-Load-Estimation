# CNN и 277 признаков

Реализация согласованного в аудите объединения. Пользователь разрешил изменение кода и запретил запуск обучения без отдельного уведомления. DataSet не читается во время разработки.

## Контракт

- `baseline.py train --model ...npz --errors-output ...csv` запускает гибрид по умолчанию; `--method auto/ridge/boosting/median` сохраняет доступ к прежним методам.
- Сегментация кузова создаёт общий ROI. 277 признаков считаются с этого ROI, а CNN получает тот же ROI с нулевыми пикселями за пределами маски кузова. Геометрических/цветовых аугментаций в первой гибридной версии нет: кэш признаков и вход CNN соответствуют одному и тому же изображению.
- Общая регрессионная голова получает CNN-вектор и нормализованные 277 признаков. Вспомогательные головы сохраняются. Нормализация оценки вычисляется только по train.
- Фиксированный train/validation split. Выбор эпохи по MAE, CSV ошибок и отдельный validation checkpoint; затем новый экземпляр модели обучается на train + validation выбранное число эпох. Метрики относятся только к validation checkpoint.
- Числовые признаки кэшируются по содержимому изображения, коду извлечения, версиям зависимостей и SHA-256 сегментаторов. В гибриде отсутствие весов пола — ошибка, без эвристического отката.
- NPZ содержит JSON-конфигурацию, версию формата, массивы state_dict и нормализацию; `allow_pickle=False`. При predict проверяется совместимость masked ROI и сегментаторов, pretrained-веса не скачиваются.
- Веса сегментаторов остаются отдельными файлами; пути можно переопределить, но SHA-256 должен совпадать с сохранённым. Имена выходных файлов должны быть новыми, существующие результаты гибрид не перезаписывает.
- CNN-обучение и реальные фотографии при разработке не запускаются. Тесты используют временные CSV/картинки, синтетические признаки и маленький заменитель backbone без скачивания весов.

## План реализации

1. Написать и запустить проверки влияния числовой ветки на прогноз, сохранения/загрузки, нормализации и формата CLI; наблюдать ожидаемые отказы до реализации.
2. Добавить HybridTruckLoadNet и Dataset для выровненных по ID признаков; сохранить прежний TruckLoadNet.
3. Добавить контракт признаков, конфигурацию сегментаторов, кэш и NPZ-сохранение.
4. Добавить orchestration фиксированного split, выбор эпохи и финальное обучение; подключить train/predict к CLI с ленивыми импортами.
5. Проверить ошибки конфигурации, границы CSV, смену весов/изображения, сохранение порядка и роль validation checkpoint.
6. Обновить README и AGENTS.md; выполнить лёгкие проверки и сообщить пользователю о необходимости обучения.

Работа выполняется в текущей директории: новые файлы CNN пользователя ещё не отслеживаются Git, изолированный checkout не содержал бы их. Коммиты и удаление файлов не выполняются.
